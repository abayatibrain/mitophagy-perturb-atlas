# ADR-0005: Pathway-definition scope
Date: 2026-05-19
Status: Proposed — awaiting Armin sign-off

## Context

The atlas's pathway view groups perturbations by membership in
known mitophagy pathways. The brief (§3.2) names two Reactome
pathway IDs as the canonical scope: R-HSA-5205685 (broad
mitophagy) and R-HSA-5205647 (PINK1/Parkin-mediated). But there
are several other plausible pathway definitions: KEGG's mitophagy
entry (hsa04137), GO biological process terms (e.g.,
GO:0000423 mitophagy), and union/intersection combinations.

Choice of pathway definition shapes which perturbations get
grouped together and what the README claims is "in the pathway."

## Options considered

### Option A — Reactome-only (R-HSA-5205685 + R-HSA-5205647)
Cleanest provenance. Reactome curation is conservative.
- Pros: single source of truth; well-versioned; convenient API
  access; matches the brief's explicit naming.
- Cons: Reactome can miss recent additions (e.g., BNIP3L receptor
  mitophagy may take a release cycle to be fully annotated).

### Option B — Reactome ∪ KEGG ∪ GO
Union of three database views.
- Pros: maximum coverage; fewer false negatives.
- Cons: each source has different annotation philosophy;
  inclusion-criterion drift between sources; harder to defend
  ("we're using the union of three" sounds like cherry-picking
  even when it isn't).

### Option C — Reactome as primary, KEGG/GO as cross-checks
Headline pathway membership uses Reactome; KEGG and GO are
computed and shown as parallel columns the way ADR-0001 handles
modalities.
- Pros: cross-source convergence is itself informative; signal
  candidates that appear in all three are higher-confidence.
- Cons: more engineering; three pathway-membership tables.

### Option D — Canonical PINK1/Parkin only, no broad mitophagy
Restrict to R-HSA-5205647. Receptor-mediated mitophagy (BNIP3,
BNIP3L, FUNDC1) is explicitly out of scope.
- Pros: tightest biological framing.
- Cons: misses substantial mitophagy biology; PRKN-anchored
  reviewers will ask why BNIP3 isn't in the set.

## Criteria for choosing
1. **Match to the brief's named scope.** The brief explicitly names
   both R-HSA-5205685 and R-HSA-5205647, suggesting both
   canonical (PINK1/Parkin) and broad receptor-mediated mitophagy
   are in scope.
2. **Defendability under hostile review.** A reviewer asking "why
   isn't BNIP3 in your scope?" should get a one-sentence answer.
3. **Cost of multi-source support.** Cross-source convergence is
   useful but adds maintenance burden.

## Decision

**Option C: Reactome as primary, KEGG and GO as parallel cross-
checks.** Headline pathway membership uses
``R-HSA-5205685 ∪ R-HSA-5205647`` (broad ∪ PINK1/Parkin) from
Reactome. KEGG hsa04137 and GO:0000423 are independently
fetched and stored. The dossier's pathway view shows the
Reactome membership as the primary, with a "also in KEGG / also
in GO" annotation per gene.

Non-canonical receptor-mediated mitophagy (BNIP3/BNIP3L/FUNDC1)
is **explicitly in scope** through the broad R-HSA-5205685
membership.

## Consequences
- Three pathway membership lookups, one primary (Reactome) and
  two cross-checks (KEGG, GO).
- The ``src/.../io/reactome.py`` client (already implemented in
  the foundational layer) handles the primary.
- KEGG and GO require their own thin clients (deferred to a
  later commit; the API contract is documented here).
- The README explicitly states the union scope.

## Open questions for Armin
1. Confirm Reactome primary + KEGG/GO cross-checks (Option C).
2. Confirm receptor-mediated mitophagy is in scope.
3. KEGG access via REST is well-documented but the data terms
