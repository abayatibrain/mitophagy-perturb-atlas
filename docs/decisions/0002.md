# ADR-0002: DepMap release pinning
Date: 2026-05-19
Status: Proposed — awaiting Armin sign-off

## Context

DepMap publishes a new release every quarter (YYQn naming, e.g.,
``24Q2``). Each release reprocesses every screen with the current
analysis pipeline, so cell-line dependency scores shift between
releases — sometimes meaningfully so for low-frequency essential
genes. For an atlas whose output is "PRKN-phenocopy candidates ranked
by similarity," the choice of release determines the ranking.

A reproducible atlas must pin to a specific release. Reading "latest"
at runtime is a defect: a reviewer who runs the demo notebook six
months later gets a different answer than the one in the README.

## Options considered

### Option A — Pin a specific release (e.g., 24Q2)
Freeze the atlas's ground-truth DepMap snapshot. The version is
recorded in ``data/README.md`` and every cached response carries the
release version.

### Option B — Always read DepMap latest
Pull at runtime. Atlas results change as DepMap reprocesses.

### Option C — Pin a release per dossier and version every output
Users can opt into a newer release if they want; the atlas
materializes one output set per pinned release.

## Criteria for choosing
1. **Reproducibility.** The README's reported PRKN phenocopy list
   must reproduce exactly when a reviewer reruns the notebook months
   later.
2. **Cost of refresh.** Pulling a new release is non-trivial
   (re-downloading multi-GB matrices, re-running similarity); the
   cost should be opt-in.
3. **Audit trail.** Cached payloads must carry the release version
   so downstream code can refuse to mix versions silently.

## Decision

**Option A: pin DepMap 24Q2.** Recorded in ``data/README.md`` and
in every cached payload's metadata. A future ADR-0002bis can bump
the pin once 24Q4 or later is published and reviewed.

## Consequences
- ``src/mitophagy_perturb_atlas/io/depmap.py`` records the release
  string at module level (``DEPMAP_RELEASE = "24Q2"``) and checks
  cached responses against it.
- The download script verifies the SHA256 of each downloaded file
  against a manifest committed to ``data/manifest_depmap_24Q2.json``.
- A release-bump is a deliberate ADR action, not a config change.

## Open questions for Armin
1. Confirm 24Q2, or specify a different pinned release.
2. Should the release version appear in every result figure caption
   as well as the README, or only in the dossier footnote?
